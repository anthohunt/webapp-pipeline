# webapp-pipeline

A three-stage agent pipeline that turns a client's idea into a live web application.

| # | Stage | Mode | End-of-stage check |
|---|---|---|---|
| 1 | **Design** | in conversation, with the client | `webapp-concevoir` |
| 2 | **Build** (+ optional video) | autonomous, on a server, restarted until green | `webapp-construire` |
| 3 | Client **review** | in conversation (human gate) | `webapp-revue` |

1. **Design**: pitch, usage questions (one at a time, A/B/C answers plus an open option), requirements, user journeys,
   user stories derived from the journeys, clickable mockup with its stories panel, **mockup test by the client**, then
   specification, roadmap and pre-flight with no questions.
2. **Build**: one milestone per launch. A builder agent builds the milestone's screens, an **independent verifier** (a
   fresh agent that built nothing) replays each story on the deployed app and returns PASS or FAIL, then tests, commit,
   production release. Once all milestones are done: the demo video, if a filming tool is plugged in.
3. **Review**: the client tests the app (and watches the video). "Good" closes the run; their feedback, kept word for
   word, becomes verifiable points and the build restarts on those points only.

Each stage has an **automatic check** (`validators/`) that judges its deliverables: while it is red, the next stage
does not start.

> The skills, docs, code comments and user-facing strings are in French.

## What is in the repository

| Folder | Content |
|---|---|
| `workflows/` | the graphs: `webapp.json` (the 3 nodes) and `webapp-design.json` (the design node alone, regenerated by `tools/sync-webapp-design.py`) |
| `skills/` | the agents' instructions, one folder each (`<name>/SKILL.md`): `pipeline-step1` to `pipeline-step4.5`, `pipeline-revue`, `pipeline-status`, `webapp-start` |
| `validators/` | the end-of-stage checks (`webapp_concevoir.py`, `webapp_construire.py`, `webapp_revue.py` and the moments they call) |
| `tools/` | the stage 2 launcher (`webapp-lancer.py`), its status (`webapp-etat.py`), mockup publishing (`publier-design.sh`), optional filming (`webapp-tourner.py`, `webapp-sonde.mjs`) |
| `mod/` | a Claude Code mod: tracking pane, band above the prompt, client decisions kept word for word (`/webapp <project>`) |
| `docs/` | the design of the 3 stages and the file contract between graph, tools and module |
| `exemple/` | `demo.sh`: end-to-end demonstration, no account needed |
| `tests/` | tests of the launcher, the status tool and the checks |
| `legacy/` | former "hardening" and "delivery" stages (`pipeline-step5/6`), outside the graph |

## The flux engine

The pipeline does not run alone: it is played by [**flux**](https://github.com/anthohunt/flux), an agent pipeline engine
(separate repository by the same author, Apache 2.0). It reads the graphs, injects the instructions, starts the agents
in Claude Code sessions and runs the checks. This repository does not copy it: clone it into `vendor/flux` (or
elsewhere, and set its path in `FLUX_HOME`).

## Install

Requirements: Linux or macOS, `git`, Python 3.10+, `pip`. To run real agents: `tmux` and Claude Code signed in to an
account.

```bash
git clone https://github.com/anthohunt/webapp-pipeline webapp-pipeline
cd webapp-pipeline
git clone https://github.com/anthohunt/flux vendor/flux    # the engine (see its own README)
python3 -m pip install -r vendor/flux/requirements.txt     # jsonschema
cp .env.example .env                                       # then adapt the paths and addresses
set -a; . ./.env; set +a
```

Check the install:

```bash
python3 "$FLUX_HOME/runtime/verifier-graphes.py" workflows/*.json   # → GRAPHES CONFORMES
FLUX_HOME="$FLUX_HOME" python3 -m unittest discover -s tests         # launcher and check tests
python3 -m unittest discover -s mod/programme/tests                  # module program tests
bash exemple/demo.sh                                                 # end-to-end demonstration
```

`exemple/demo.sh` creates a run called "covoiturage-facile" (an invented project), writes the brief of the design node
with its instructions, shows the stage 1 check red on an empty run, then green for the stage checks on a finished sample
run, reads the build status and asks the launcher what it would do. **All of this runs without an account.** What
follows (the design conversation and the build agents) requires Claude Code signed in.

## Usage

1. **New run**: in Claude Code, with the mod, `/webapp <project>`; without the mod, the `/webapp-start` skill
   (created by `python3 $FLUX_HOME/runtime/new-run.py webapp '<project>'`).
2. **Design** with the client in the same session. The mockup is published over HTTP by `tools/publier-design.sh`
   (settings `DESIGN_PUBLISH_DIR`, `PUBLIC_BASE_URL`) so the client can open it without an account.
3. **Build**: `python3 tools/webapp-lancer.py <workspace>` starts stage 2 detached and restarts it until the check is
   green; `python3 tools/webapp-etat.py <workspace>` tells you where it stands (one JSON line).
4. **Review**: the `pipeline-revue` skill (or the mod's pane); feedback restarts the build on those points only.

## Settings

Everything that depends on the machine goes through environment variables, listed with sample values in `.env.example`:
location of the engine and the runs, the agents' account (`WEBAPP_MOTEUR`, an engine from flux's `moteurs.json`),
Supabase and Vercel token file (`WEBAPP_STACK_ENV`, **outside the repository**), mockup publishing, video
(`WEBAPP_VIDEO=0` by default), SSH host of the runs server.

The stack imposed on the apps it builds is React + Vite, Supabase, Vercel: one Supabase account and one Vercel account
serve all projects. Their tokens never go in a repository; each app gets its own keys in its `.env.local`, ignored by
git.

## Demo video (optional)

`tools/webapp-tourner.py` writes the text of each sequence with an agent, generates the voice, films the live app and
publishes an editing table. It requires an external filming tool, **not provided** here (`TOURNAGE_MOD_HOME`,
`TOURNAGE_SKILL_HOME`). Without it, leave `WEBAPP_VIDEO=0`: the checks then ask for no video and the client reviews the
app alone.
